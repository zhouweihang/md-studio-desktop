### 本轮发现并修复的缺陷

- **现象**：IME-4 首次执行失败，页面抛出两个错误：
  1. `Decorations that replace line breaks may not be specified via plugins`（CM6 硬性约束）
  2. `Cannot destructure property 'tile' of 'parents.pop(...)' as it is undefined`（`@codemirror/view` 视口迭代崩溃，是第 1 个错误的连带后果）
- **根因**：实时预览的 `ViewPlugin` 在中文组合期间跳过装饰重建（REQ-008 的正确行为），但同时**没有把旧装饰映射到新文档坐标**。组合提交会在文档里产生变更，旧装饰区间因此停留在过期位置，一旦跨过换行就被 CM6 判定为「插件提供了跨行替换」。
- **修复**：`renderer/editor/live-preview.ts` 的插件 `update()` 在 `docChanged` 时先 `decorations.map(changes)` / `atomicRanges.map(changes)`，再按 `shouldRebuild()` 决定是否重建。组合期仍然不重建（保留 IME 手感），但坐标始终有效。
- **回归**：修复后 IME 四条序列全通过，且既有 291 条单元测试与 13 条 E2E 全绿（装饰映射不改变渲染结果）。

## 3. 人工项执行步骤（待真人回填）

前置：`cd md-studio && npm run dev`（或使用构建产物），在微软拼音输入法下操作；每步结束后记录「通过/失败 + 现象」。

### IME-5 输入法方案切换（拼音 ↔ 双拼 / 五笔）

1. 用拼音输入一段文字（≥20 字），确认预览渲染正常。
2. 切换到「微软双拼」，继续在同一段落输入 10 个字，观察是否串字、丢字或光标跳动。
3. 切换到「微软五笔」，重复上一步。
4. 切回拼音，在**表格单元格**内输入含全角标点的一句话。
5. 判定：三种方案下都不丢字、不串位；切换后第一键即生效；文档结构（标题/列表/表格）不被破坏。

### IME-6 候选窗定位、翻页与上屏位置

1. 在**长文档中部**点击（滚动到中部后）输入拼音，观察候选窗是否紧跟光标、不超出窗口边界。
2. 在**表格单元格内**输入拼音，观察候选窗是否遮挡关键内容、上屏后表格是否错行。
3. 输入长拼音串（如 `zhonghuarenmingongheguo`）并用 `-` / `=`（或 PageUp/PageDown）翻页选词，确认选中词落在光标处。
4. 在**行首**输入，确认候选窗不超出左边界；在**窗口右/下边缘**输入，确认候选窗自动翻转方向。
5. 组合中按 Esc 取消，确认文档无残留拼音、无空行插入。
6. 判定：候选窗位置合理、翻页可用、上屏位置准确、取消干净。

## 4. 判定标准（与 RFC-002 对齐）

- 组合期间**不重建**装饰（`tests/editor/ime.test.ts` 的 `shouldRebuild` 判定矩阵 + 本清单 IME-1/IME-4）。
- 组合期间旧装饰必须**坐标有效**（本轮修复项，IME-4 覆盖）。
- 提交后文档只保留最终文本，不残留拼音；撤销不损坏文档。
- 全程无 `pageerror`；状态栏统计与预览随输入更新。
